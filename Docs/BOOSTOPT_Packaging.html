Packaging & closed-source distribution

BOOSTOPT ships under a commercial EULA and the engine is not published anywhere. A licence governs what people may legally do; it does nothing about what they can see. This document is the second half.

0The problem: a pure-Python wheel ships your source

A py3-none-any wheel is a zip of .py files. Measured on the real artifact:

$ python -c "import zipfile; print(len([n for n in zipfile.ZipFile(
      'boostopt-0.1.0-py3-none-any.whl').namelist() if n.endswith('.py')]))"
80

That includes boostopt/engine/gate.py — the trusted core, the only place in the codebase that returns accepted=True. Anyone can pip download boostopt and read it.

Shipping only .pyc is not a fix. pycdc and similar reconstruct readable source, and you lose tracebacks. Worst trade available.

1Compiling with Nuitka

python -m nuitka --module boostopt --include-package=boostopt --output-dir=nuitka-out

Produces one boostopt.cpython-311-x86_64-linux-gnu.so (~4.1 MB). Verified:

CheckResult
boostopt.__compiled__True — loader nuitka_module_loader
.py files on disk0
boostopt demo from the binary aloneACCEPT, −66.7% p50, Rung 3 clean
The boostopt executable against the .soworks — pip's console script is agnostic

__file__ still reports a .py path — Nuitka synthesises it. Do not use that to test whether a build is compiled; use __compiled__. Two directories matter and they are opposite: compile from the repo root (Nuitka needs the source folder), verify from the directory holding only the .so (at the repo root, boostopt/ shadows it).

2What broke

The first compiled build silently lost its data files. importlib.resources has no filesystem package to read once everything is one .so:

Modelfile : False | base: None        # boostopt init downgrades to the bare base model
demo      : False                     # boostopt demo cannot find its sample

Neither raised. They returned “not found”, which the code treats as “not one of ours”. A pure-Python test run passes completely while the shipped artifact is broken.

3The fix: assets are module constants

  • boostopt/runtime/models/__init__.py → MODELFILES: dict[str, str]
  • boostopt/examples/__init__.py → DEMO_NAME, DEMO_SOURCE

provision.bundled_modelfile() writes the text to a temp file when ollama create -f needs a path. There is no [tool.setuptools.package-data] section any more, which removes the class of bug where a glob is forgotten and a file exists in a checkout but not the wheel.

Guarded by tests/invariants/test_boundary.py: test_runtime_assets_are_module_constants_not_data_files and test_no_stray_data_files_left_inside_the_package.

4Remaining work before compiled wheels ship

  1. A build matrix. py3-none-any becomes platform- and version-specific: manylinux x86_64/aarch64, macOS x86_64/arm64, Windows × CPython 3.11/3.12/3.13 — roughly 9–12 wheels per release. Use cibuildwheel, with Nuitka inside each matrix job.
  2. Wheel tagging. A wheel containing a .so must be tagged cp311-cp311-manylinux_2_17_x86_64 or pip will install a Linux binary on macOS and fail at import.
  3. boostopt_server stays out, as today — see the open-core boundary tests.
  4. Tracebacks. Compiled frames report synthetic paths; decide whether crash reports need a privately-kept symbol map.
  5. Build time. ~10 minutes for 84 C files with a cold ccache.

For apt, a different mode

python -m nuitka --standalone --onefile boostopt/surfaces/cli/__main__.py \
    --output-filename=boostopt

A genuine standalone binary with Python and every dependency bundled — no interpreter on the target. Bigger (~50–80 MB) and slower to build, but the right artifact for a .deb.

5What compilation does and does not buy

It raises the cost of reading the engine from unzip to reverse-engineer a stripped binary. It is not DRM and it does not stop a determined competitor. The enforceable protection is the EULA; compilation is the practical deterrent.

Weigh that against the matrix cost. A plausible alternative is shipping readable Python under the same EULA and competing on brand, support, and the hosted tier — which is what most commercial developer tools do.
